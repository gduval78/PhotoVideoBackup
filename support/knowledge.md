# PhotoVideoBackup — support knowledge

Curated notes for the support agent. **Keep this file up to date at every store delivery** (see the "Documentation maintenance" checklist in CLAUDE.md): add each new feature, limit or known issue, with the version it appeared in.

## Versions
- iPhone / iPad (and Apple-silicon Mac as "Designed for iPad"): 2.7.1 (backup profiles, 12 languages; 2.7.1 adds the SD card → NAS templates).
- Android: 2.7.1 (backup profiles, 12 languages; same version number as iOS; same engine and same features as iOS except iCloud Drive, which does not exist on Android).
- A backup started on one platform is recognised by the other (the hidden `.pvb-index.json` at each destination root is shared).

## Pro
- One-time purchase, no subscription. Free: back up the photo library to one destination, browse and preview backups (LUT preview included). Pro: SD/USB camera sources, second destination (mirror), NAS, LUT grading to H.265.
- Restore: on the upgrade screen (Settings → Upgrade to Pro), tap **Restore Purchases**, signed in with the same Apple ID (iOS) or Google account (Android).
- Refunds and charges are handled by Apple / Google, not by us.

## Backup profiles (iPhone / iPad, 2.7.0)
- Each backup is a **profile**: a card on the **Backups** tab with its own source, destination(s), NAS and settings (folder structure, file naming, max files, extra file types). Tap **Run**; long-press a card → **Settings** to edit, rename or delete. **New backup** (+) offers six templates (2.7.1): photo library → folder / NAS / folder + NAS; camera or SD card → folder / NAS / folder + NAS. A folder can be a drive or an iCloud Drive folder (detected automatically; iCloud is slower and depends on iOS and iCloud space). On a backup card the badge shows how the data travels: cable = local, Wi-Fi, or mobile data (SIM / eSIM) for a NAS or cloud folder, following the current network. Before 2.7.1 (2.7.0) the templates were: photo library → external drive / NAS / iCloud Drive; camera or SD card → external drive; external drive → iCloud Drive; photo library → drive + NAS.
- **Free = one backup** (photo library → one folder). **Several backups, a second destination, a NAS, camera/USB sources and LUT grading are Pro.** If Pro is lost the first backup keeps working and the others show *Unlock* — nothing is deleted.
- **The Advanced tab no longer exists.** An existing setup is turned into profiles automatically at the first launch of 2.7.0; nothing to reconfigure. Settings → Backup now holds the *defaults for new backups*.
- A card shows **Reconnect** when its source (card/drive) or a destination folder cannot be reached: tap it and pick the folder again. Replacing a drive: Settings of the backup → *Choose another folder…*. Several destinations: Settings of the backup → *Add a destination* (Pro).
- Each backup can use **its own NAS**; Browse lists every NAS and every profile folder.
- **Run opens a summary screen first** ("Ready to back up?"): the source, then each destination with a pictogram for its kind (drive, NAS, cloud folder, or the phone itself in orange with a warning that the destination is on the device, not on an external drive), and the power state when *Only run on power* is on. **Start backup** launches it, the cross cancels. iPhone since 2.7.0; **Android since 2.7.1 (code 20707)** — earlier Android builds started the backup directly on tap.
- Android does not have profiles yet (same screens as before).

## Servers and WebDAV (iPhone / iPad and Android, 2.8.0 — NOT RELEASED YET: do not tell users it exists until the release)
- **New backup is now: choose what to back up** (Photo library / Gallery, or Camera or SD card — Pro), **then the same editor used to change a backup**: *Add a destination* → **A folder…** (a drive, a card, any folder of Files / the system picker, iCloud Drive and Google Drive included) or **A server ▸** *NAS (Synology, QNAP…)* (SMB) / *Nextcloud, pCloud or WebDAV server*. The eight templates are gone from the UI (old profiles still open). A backup can have **several servers and folders** (Pro); each server's password is in the iOS Keychain / Android Keystore. A server (NAS, Nextcloud, pCloud, S3 later) is a *typed connection*; a profile saved by a newer build with an unknown server type is kept as it is (shown as "needs a newer version"), never lost.
- A backup can go to a **WebDAV server** (Nextcloud, ownCloud, pCloud, Synology/QNAP WebDAV, Hetzner Storage Box…) — **Pro**, like the NAS.
- Server address is **https only**. Nextcloud: `https://server/remote.php/dav/files/NAME/`. pCloud: `https://ewebdav.pcloud.com/` (EU account) or `https://webdav.pcloud.com/` (US). With two-factor authentication use an **app password**. Password in the iOS Keychain.
- **Self-signed certificate**: *Test connection* says the certificate is not trusted and shows its fingerprint; *Trust this certificate* pins it (only that exact certificate is accepted afterwards; a different one reads "certificate has changed"; *Forget this certificate* removes it). Plain http is not accepted.
- **Large files**: Nextcloud/ownCloud get videos above 100 MB in 10 MB pieces (resumable). Any other server (pCloud, Synology…) gets one request per file; a server or proxy limit shows "The server refused this file size — check its upload limit." (HTTP 413) → raise `upload_max_filesize` / `post_max_size` / proxy body size, or use a drive or NAS. pCloud itself says WebDAV is not made for very large backups. Not validated with multi-GB files.
- Verified on a Docker Nextcloud (self-signed) and a real pCloud WebDAV account. **Not validated**: Synology WebDAV Server, Hetzner, ownCloud, pCloud with 2FA by e-mail. pCloud's Crypto Folder is not reachable through WebDAV.
- Browse lists every server (NAS or WebDAV) the same way and opens files by downloading them (no thumbnails); **LUT Grade works on every server** (download → grade → upload). A backup with a server is not readable by builds older than 2.8.0 (kept aside, not lost).
- **A mistyped server address** (e.g. `ewebdav.pcloyd.com`) answers a redirect: the app says "The address redirects somewhere else. Check the server address." **A damaged or momentarily unreadable index** (`.pvb-index.json`) is read again (3 attempts); one that exists but cannot be read is never overwritten, and one that stays undecodable is kept as `.pvb-index.corrupt.json`.

## Common situations
- **"Not connected" source or destination after ejecting and reinserting a card or drive**: tap **Reconnect** (the system gives the app a new access each time a volume is mounted). Name and type are kept.
- **Backup button disabled**: no device name set (Settings → Device → Folder name), or the destination is not connected.
- **A backup stopped as "Partial"**: the report says why — Stop tapped, file limit reached (Settings → Backup → Max files per session, empty = unlimited), or a destination disconnected. Reconnect and run again; files already copied are skipped.
- **Nothing is copied on the second run**: normal — every file already backed up is recognised (even if edited since) and skipped.
- **File naming**: only files copied after the profile is switched on are renamed; existing files keep their names. Nothing is ever overwritten (`-1`, `-2` suffix for a different file with the same name).
- **NAS timeout**: the NAS is not reachable — same Wi-Fi or VPN (Tailscale) on, SMB sharing enabled, NAS firewall. Use the NAS's IP as host.
- **Mac (Designed for iPad)**: the first time, tap **Choose…** again to create a properly scoped folder access.
- **Android: photos have no GPS data in the backup**: the "location of your photos" permission was refused; grant it in system settings, otherwise Android strips GPS from the files it hands over.
- **Android: a destination in the phone's own storage does not show in the gallery**: intended (`.nomedia`), so the backup is not backed up again.
- **Android: sources/destinations written by Android do not keep the original modification date** (the system file API cannot set it).
- **iPhone almost full**: backups stream straight to the destination; a NAS-only backup needs room for one file at a time.
- **iCloud Drive destination (iPhone only)**: local copies are released once iCloud confirms the upload.
- **iCloud Drive destination: iPhone fills up during a big backup (known limit)**: iOS uploads on its own schedule, so copies pile up locally; the app releases them as iCloud confirms, but free space can also fall because of Photos' iCloud download cache (Optimize iPhone Storage — hypothesis). Advise: charger + Wi-Fi, let iCloud finish uploading, run again; for large libraries prefer an external USB-C SSD. From 2.6.1 a full iPhone is reported as such ("Not enough free space on this device…", session Partial "iPhone storage is low"); with 2.6.0 the log and report wrongly said "destination disconnected" although the real cause was full storage. The run is partial, nothing is lost; `.pvb-index.json` failing to write on a full volume is harmless (rewritten next run).
- **Backup paused "waiting for storage to free up" (iPhone, 2.6.1)**: the Photos backup keeps at least 1 GB free on the iPhone (plus the file's size when writing to iCloud Drive / a NAS-only staging copy). It pauses and resumes by itself when space returns (iCloud uploads finishing, iOS purging caches); after ~10 min without gain (30 s if nothing is left to release) it stops as Partial with "iPhone storage is low" — nothing is lost, free space and run again. Not available on Android / for SD-card sources (they never use the phone's storage).
- **Partial "a destination is full or reported an error" (2.6.1)**: with several destinations, one of them (e.g. iCloud Drive) was full or failed while the others carried on; the files missing there are listed as failed for that destination in the Report. Free space there and run again — what is already backed up is skipped.
- **iCloud Drive: is my backup really in iCloud? (2.6.1)**: open the session Report — the "iCloud Drive" section shows, read live from iOS, how many files are in iCloud (space freed / still on the iPhone), uploading, waiting, or in error (with iOS's message, e.g. "cannot connect to the server" = the phone cannot reach iCloud: check Wi-Fi/VPN/Low Data Mode, let it cool and charge). Tap *Refresh iCloud status*. A file only counts as safe in iCloud once it shows as uploaded; iOS decides when.
- **"Your iCloud storage is full" (2.6.1)**: iOS refuses uploads (`-1003`, "quota insufficient") — the iCloud account has no room left; a whole photo library of DNG files rarely fits next to iCloud Photos and device backups. The backup stops as Partial; free iCloud space (Settings → name → iCloud → Manage Storage) or back up to an external drive or a NAS instead. Originals are untouched. Error `-1004` ("cannot connect to the server") is a network problem instead.
- **Android: Google Drive / OneDrive / Dropbox as a destination (2.6.1)**: allowed, but slow and indirect — the cloud app uploads on its own schedule, shares its quota with the user's other data (Google Drive's 15 GB is shared with Gmail and Google Photos) and may keep files on the phone meanwhile. With under 10 GB free the app warns before starting. For a large library recommend an external drive or a NAS. Google Photos cannot be a destination; the gallery source only sees files that are on the phone (originals removed by Google Photos "Free up space" are not backed up).
- **Android: a re-run that skipped files and failed one showed "failed" (before 2.6.1)**: fixed — a session is only "failed" when nothing at all is backed up.
- **A file appears as `NAME-1.ext` next to a smaller `NAME.ext` (before 2.6.1)**: an earlier copy was interrupted (disk full) and left a truncated file. Fixed in 2.6.1; with 2.6.0, delete the truncated original in the destination, then run again.
- **Battery drain during a long backup / two drives at once (guide, 2026-11)**: the phone has one USB-C port and bus-powered SSDs draw power from it. Use a USB-C hub with Power Delivery pass-through: two SSDs + a power bank (or charger) on the hub's charging port — the power bank feeds the hub, which powers the SSDs and charges the phone. Needs a hub with a USB-C PD input and a power bank with PD output (30 W+ comfortable with two SSDs). Android: OTG hub with power input. Diagram in the guide, section "What you need" (`hub_power`). Reported by a tester who backed up to 2 SSDs + a power bank. Per-backup option **Only run on power** (backup settings, iOS + Android): the backup refuses to start unless the phone is charging (it cannot tell a power bank from a charger); a backup with a disconnected destination is already refused. Not checked during the run.

## Not supported / limits
- LUT grading only handles `.mp4` and `.mov`; per-video selection (never "grade all").
- Deleting source files after a backup only offers files copied *and* verified in that session, behind a 4-digit code.
- Browse on a NAS shows no thumbnails (files are downloaded on demand).
